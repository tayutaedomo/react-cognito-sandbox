# MFA・デバイスの情報確認

POC 008 のデバイス記憶に続き、サインイン中の本人が Cognito とブラウザの保存情報を照合する方法を検証します。Managed Login と SRP の両経路を維持します。

## 検証の概要

| 確認すること | 取得元 | 表示方法 |
| --- | --- | --- |
| TOTP の有効設定 | Amplify Auth の本人用 API | TOTP の設定グループ |
| デバイスの登録と信頼状態 | バックエンド経由の AdminListDevices | デバイスのカードと初期マスクの raw データ |
| ブラウザの保存情報 | 現在のサイトの localStorage | デバイス・トークン・その他のグループ、値は初期マスク |

## 情報取得の構成

本人用の ListDevices / GetDevice の実環境応答では、信頼状態を取得できませんでした。そこで本人限定の `GET /api/me/devices` を追加し、AdminListDevices の信頼状態属性を取得します。対象ユーザーは検証済み JWT の claims から決定し、ブラウザから任意のユーザー名を指定できない構成です。

localStorage のデバイスキーと Cognito のデバイス ID を照合します。登録の存在と信頼済み状態は別に表示します。SRP は通常のログイン方法として表示し、Managed Login も利用できます。呼び出し関係と保存項目の意味は実装説明を参照してください。

## 確認手順

1. Managed Login または SRP でサインインし、「MFA 設定」を開きます。
2. TOTP の設定と、Cognito の登録済みデバイスの信頼状態を別々に確認します。
3. 「localStorage を読み込む」で保存情報を取得し、対応する Cognito のデバイスを確認します。
4. raw データは必要な項目だけ明示操作で表示し、確認後は閉じます。実ユーザーの秘密情報をキャプチャやログへ保存しません。
5. SRP 経路で信頼登録・解除した場合は一覧を再取得します。MFA 省略の確認は新しい SRP ログインで別途行います。

## 検証結果と制約

- バックエンドの単体テストで本人限定の取得、ページング、エラー処理を確認しました。
- モックの単体テストとブラウザテストで、保存情報の分類・デバイス照合・初期マスクを確認しました。
- 実 Cognito のブラウザテストで、Managed Login 後の一覧再取得と、SRP ログイン後の画面移動・再読み込みを確認しました。
- localStorage は現在のサイトの保存領域だけを読み取ります。他のサイト・ブラウザ・端末の保存情報は取得できません。Cognito の内部情報や TOTP シークレットを管理者 API から取得する機能はありません。
- Cognito の信頼状態の表示と、次回のログインで MFA が省略されることは別の確認です。Managed Login では記憶済みデバイスによる MFA 省略を利用できません。
