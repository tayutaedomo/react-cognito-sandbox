## 新しい POC の記録

`005-検証テーマ.md` のように番号とテーマを含むファイルを追加し、この一覧からリンクします。

- 「何を確かめ、どんな結論を得たか」を独立して説明できるテーマを1文書にします。文書の長さを揃える必要はありません。
- モックや E2E など検証を支える仕組みは、それを利用するテーマに含めます。
- 目的、検証内容・結果、制約・未検証事項、関連 ADR、実行手順へのリンクを記載します。
- Issue・PR は変更の単位、POC 文書は検証テーマの単位として扱い、必ずしも1対1にはしません。
- 過去の検証結果と現在の構成は区別し、構成が変わった場合はアーキテクチャ文書も更新します。

## 過去の記録と現在の説明

POC 文書は検証時点の記録として保持します。後続の実装を過去の検証結果に混ぜず、独立した検証テーマは別文書に記録します。誤りを訂正する場合は訂正内容を明記し、関連する後続文書へのリンクを追加できます。現在の操作方法と構成は README・アーキテクチャ・実装説明を更新します。

CI・Lint・Formatter などの開発基盤の導入だけを理由に POC を増やしません。使い方は開発用ドキュメント、重要な設計判断は ADR に残します。ADR も過去の判断を保持し、後続の判断を別の ADR から参照します。
