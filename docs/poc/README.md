## 新しい POC の記録

`005-検証テーマ.md` のように番号とテーマを含むファイルを追加し、この一覧からリンクします。

- 「何を確かめ、どんな結論を得たか」を独立して説明できるテーマを1文書にします。文書の長さを揃える必要はありません。
- モックや E2E など検証を支える仕組みは、それを利用するテーマに含めます。
- 目的、検証内容・結果、制約・未検証事項、関連 ADR、実行手順へのリンクを記載します。
- Issue・PR は変更の単位、POC 文書は検証テーマの単位として扱い、必ずしも1対1にはしません。
- 過去の検証結果と現在の構成は区別し、構成が変わった場合はアーキテクチャ文書も更新します。
