# ADR 0012: 本人限定の管理者 API でデバイスの信頼状態を表示する

## 目次

- [トレードオフと代替案](#トレードオフと代替案)

## ステータス

提案。ADR 0011 の実験用 SRP の扱いを見直し、デバイス情報を確認する方法を追加する。

## 背景

本人用の `ListDevices` / `GetDevice` の実環境応答では信頼状態を取得できない。登録の有無と信頼済み状態は異なり、ユーザーが Cognito とブラウザの保存情報を照合するには正確な信頼状態が必要になる。

## 決定

`GET /api/me/devices` から `AdminListDevices` を全ページ取得する。対象ユーザーは JWT Authorizer が検証し、Lambda Web Adapter が転送する claims から決定する。任意の Username を受け付けず、IAM は対象 User Pool の読み取り権限だけを追加する。`AdminGetDevice` と `AdminGetUser` は必要な情報が既存 API で得られるため追加しない。

SRP を通常のログイン方法として表示し、Managed Login も維持する。MFA 設定画面は TOTP、Cognito のデバイス、ブラウザ保存情報に分ける。Cognito の raw データと現在のサイトの localStorage の全値は初期マスクし、明示操作で表示する。保存情報の診断は読み取りのみとし、補足説明は各グループへまとめる。

## トレードオフと代替案

- 本人用 API のみ：管理者権限を不要にできるが、信頼状態の確認という要件を満たさない。
- ブラウザに信頼状態を別途保存：Cognito 側の変更とずれるため、正しい現在値として採用しない。
- 管理者 API：バックエンドと IAM の変更が必要。本人限定とページングを単体テストし、認証済みでも別ユーザーを指定できない構成にする。
- raw 値の初期表示：比較しやすい一方で秘密情報を不用意に露出するため、初期マスクと個別の表示操作を採用する。表示した情報はスクリーンショットやログへ保存しない。
