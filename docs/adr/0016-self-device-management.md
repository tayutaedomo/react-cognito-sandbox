# ADR 0016: 本人のデバイス信頼解除と登録削除を分ける

## 目次

- [ステータス](#ステータス)
- [背景](#背景)
- [決定](#決定)
- [トレードオフと代替案](#トレードオフと代替案)

## ステータス

提案。

## 背景

デバイス一覧は本人限定の管理者 API で読み取れるが、一覧から操作できなかった。SRP 画面の「信頼を解除」は実際にはデバイス登録を削除しており、信頼状態と登録の違いを説明できていなかった。

## 決定

一覧から「信頼を解除」と「デバイス登録を削除」を別操作で提供する。前者は `AdminUpdateDeviceStatus` で `not_remembered` にし、後者は `AdminForgetDevice` を呼ぶ。API Gateway の検証済み本人情報から対象ユーザーを決め、クライアントからのユーザー名は使用しない。IAM 権限は既存 User Pool に限定する。

どちらも対象を表示して確認後に実行する。未信頼のデバイスでは信頼解除ボタンを無効にする。MFA 有効状態や現在のブラウザ識別の有無では操作を制限しない。登録削除後は、このブラウザに一致する deviceKey・deviceGroupKey・randomPasswordKey だけを消し、他ユーザーの情報・トークンは残す。

新しい SRP サインイン成功後の Amplify による自動登録は維持する。手動登録ボタンは追加しない。セッション失効は別操作として扱う。アクセスログはルートのテンプレートを使い、デバイスキーを記録しない。

## トレードオフと代替案

- 本人の Access トークンを使う API：実現できるが、既存の本人限定バックエンドと認証情報の検証方式を共用する。
- 登録削除だけを提供する：実装は少ないが、信頼状態を変えて登録を残す検証ができない。
- 他ブラウザの localStorage も削除する：遠隔操作できないため、Cognito の登録削除によって次回の信頼済み認証を止める。

登録・信頼・削除の状態図と操作は [実装説明](../trusted-device-implementation.md#登録信頼削除の違い) を参照する。
