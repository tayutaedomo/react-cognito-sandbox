# ADR 0015: SMS MFA を東京の SNS サンドボックスで検証する

## 目次

## ステータス

提案。

## 背景

TOTP・メール・信頼するデバイスの構成を維持して、日本の携帯番号1件で SMS MFA を確認したい。既存の Terraform AWS プロバイダーは SNS 経由の `sms_configuration` を扱える。

## 決定

Cognito と同じ東京リージョンの SNS 経由で SMS を送る。サンドボックスを維持し、番号確認・配送確認を先に行う。専用番号購入と送信上限引き上げは行わない。復旧方針は既存の `admin_only` を維持する。

Cognito 用 IAM ロールに `sns:Publish` を許可する。電話番号への直接送信は SNS トピック ARN で権限を限定できないため、リソースは `*` とする。ロールの信頼ポリシーは Cognito サービス・同一アカウント・東京の User Pool ARN・固有の External ID で制限する。User Pool とロールの循環参照を避けるため ARN のプール ID 部分はワイルドカードにする。

SMS とメールの属性確認・設定表示は共通コンポーネントを使い、優先設定は3方式で処理する。プールへの追加だけで全ユーザーの SMS MFA を有効にはしない。

## トレードオフと代替案

- AWS End User Messaging SMS の直接経路：送信元を明示できるが、今回必要な最小の SNS 構成で検証し、直接経路への移行は行わない。
- 本番へのサンドボックス解除：一般の電話番号へ送信できるが、今回の宛先1件の検証には不要。
- 自己パスワード復旧との併用：配送先と MFA の組み合わせが増えるため、既存の管理者復旧を維持する。

検証範囲と手順は [POC 011](../poc/011-sms-mfa-sandbox.md) を参照する。
