# ADR 0011: 信頼するデバイス POC に専用 SRP ログインを使う

## 目次

## ステータス

提案。ログイン後の一覧参照と SRP の位置づけは [ADR 0012](./0012-device-diagnostics-admin-api.md) で見直す。

## コンテキスト

既存の Hosted UI を維持しつつ、Cognito のデバイス記憶による MFA 省略を評価したい。デバイス認証は User Pools API のサインイン経路で利用する。OAuth / Hosted UI のログイン経路では、記憶済みデバイスによる MFA 省略を利用できない。

## 決定

既存の Hosted UI を変更せず、開発用画面に `USER_SRP_AUTH` の実験ログインを追加する。Cognito のデバイス設定は User Opt-In とし、新しい端末では TOTP を要求する。専用ユーザーで端末記憶・同じ端末の再ログイン・別端末・信頼解除を確認する。

ログイン後の一覧参照は、両経路の本人の Access トークンと `ListDevices` で行う。信頼状態を取得できない場合は不明と表示し、一覧への登録だけで信頼済みと断定しない。状態表示のための管理者 API は追加しない。

## 結果

通常のログイン経路を変えずに、デバイス認証を分離して評価できる。専用ユーザーの資格情報と TOTP シークレットが必要になる。Cognito の記憶デバイスに TTL はなく、期限ポリシーは別途アプリ側で設計する。

## 代替案

- Hosted UI だけで記憶済みデバイスによる MFA 省略を試す: そのログイン経路ではデバイス認証を利用できないため採用しない。
- 本番の認証経路を SRP に置き換える: POC の評価に不要で、既存のログイン体験に影響するため採用しない。
- 信頼状態を管理者 API で取得する: バックエンドに権限追加と本人への情報制限が必要になる。今回は本人の API による一覧参照と、SRP 再ログインでの MFA 要求の確認に留める。
