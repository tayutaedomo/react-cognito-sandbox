# ADR 0006: Cognito セキュリティとログインアタック防御・ログ戦略

## 1. コンテキストと背景

現在のアーキテクチャでは、フロントエンド (Amplify) へのトラフィックは WAF (us-east-1) で、API へのトラフィックは API Gateway のアクセスログと Lambda の JSON 構造化ログ (Powertools) で追跡・保護しています。

しかし、**Cognito のログイン画面 (Managed Login)** に対して、悪意あるユーザーが「パスワードの総当たり攻撃 (ブルートフォースアタック)」などを仕掛けた場合、現在の構成では以下のような課題があります。
1. **防御の限界**: Cognito 自体が持つデフォルトのレート制限やアカウントロック機能は働きますが、自社要件に合わせた IP 制限やきめ細やかなレート制限ができません。
2. **ログの欠如**: ログインに失敗した履歴や、どこからアタックを受けているかといった「ユーザーアクティビティログ」が、デフォルトでは CloudWatch Logs に出力されません（API Gateway に到達する前の出来事であるため）。

これらの課題を解決し、本番環境のセキュリティと監査要件を満たすための戦略を定義します。

## 2. 検討した選択肢

### オプション A: Cognito への AWS WAF アタッチ
AWS WAF を Cognito User Pool に直接アタッチするアプローチです。
- **機能**: レートベースルール (例: 5分間に100回以上のリクエストをブロック) や、特定の社内 IP からのみアクセスを許可する IP 制限が可能。
- **ログ**: WAF のアクセスログ (CloudWatch) に、攻撃元の IP アドレスや URI などの HTTP リクエスト情報が記録されます。
- **コスト**: WAF の基本料金 ($5/月) ＋ リクエスト回数課金。ログイン操作のリクエストに対してのみ課金されるため、MAU (月間アクティブユーザー) が数万人規模の B2C サービスでもコストが跳ね上がらず、非常に安価（月額 $10 前後）に抑えられます。
- **制約**: Amplify (フロントエンド) の WAF は **グローバル (us-east-1)**、Cognito の WAF は **リージョナル (ap-northeast-1)** となるため、1つの WebACL リソースを共有することはできません。IaC (Terraform) で同じ IP リスト変数などを両方に流し込む設計が必要です。

### オプション B: Cognito Advanced Security Features (CASF) の有効化
Cognito が提供する「高度なセキュリティ機能 (CASF)」を有効化するアプローチです。WAF のような HTTP レベルの制御ではなく、認証の振る舞い (コンテキスト) に着目した高度な防御とログを提供します。

- **機能**:
  1. **漏洩認証情報のチェック**: 入力されたパスワードがダークウェブ等で漏洩済みリストに載っている場合、ログインをブロックしたりパスワード変更を強制します。
  2. **適応型認証 (リスクベース認証)**: いつもと違う場所、未知のデバイス、不審な IP からのログインにリスクスコアを付け、自動的に MFA (多要素認証) を要求したりブロックしたりします。
- **ログ**: これを有効にすると、待望の **「ユーザーアクティビティログ」が CloudWatch Logs に出力されるようになります**。ログインの成功・失敗、検知されたリスクレベル、デバイス情報などが JSON 形式で記録されます。
- **コスト**: **MAU (月間アクティブユーザー) ベースの従量課金**です。
  - 数十〜数百 MAU の社内・業務用アプリであれば、追加コストは月額数ドル未満（MAU 10 なら $0.50 程度）となり、WAF の基本料 ($5) よりも安価に導入できます。
  - しかし、1万〜10万 MAU を超える B2C サービスの場合、MAU 単価 ($0.05〜) が重くのしかかり、数万円〜数十万円/月のコスト増となるため注意が必要です。

## 3. 決定事項

当面の POC 環境においては現状維持としますが、本番環境へのデプロイを見据えた場合、**「対象アプリの想定 MAU（ユーザー規模）」と「ログ監査要件」に応じて A または B（あるいは両方）を選択する** ガイドラインとします。

1. **業務用 / B2B アプリ (MAU が少なく、高度な監査ログが欲しい場合)**
   - **CASF (オプション B)** の導入を第一候補とします。コスト増が極めて小さく、CloudWatch に詳細な認証ログが残るため、開発・運用コストのコストパフォーマンス (タイパ) が最も高くなります。
   - さらに強力なアクセス元制限 (社内 IP のみ許可など) が必要な場合は、オプション A (WAF) を併用します。

2. **コンシューマー向け / B2C アプリ (MAU が多く、コストを抑えたい場合)**
   - CASF はコストが致命的になりやすいため、**AWS WAF のアタッチ (オプション A)** を第一候補とします。
   - レート制限を用いて入り口でのブルートフォース攻撃を安価に防ぎ、攻撃ログは WAF のログとして監視するアプローチを基本設計とします。

## 4. 影響と今後のアクション
- 本 ADR に基づき、次回の POC イテレーション、または本番デプロイ要件の定義時に、Terraform コードへ対象の設定 (`aws_wafv2_web_acl_association` または Cognito の `user_pool_add_ons` ブロック) を実装します。
