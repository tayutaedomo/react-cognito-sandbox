# ADR 0013: AWS 非接続の検証を PR の CI にする

## 目次

- [背景](#背景)

- [トレードオフと代替案](#トレードオフと代替案)

## ステータス

提案。

## 背景

認証・MFA・デバイスの変更に対して単体テストとモック E2E が増えている。PR ごとに同じ検証を実行し、確認漏れを減らす必要がある。実 Cognito の E2E は資格情報を必要とし、設定やデバイス記録を変更する場合がある。

## 決定

GitHub Actions で frontend・backend・Terraform・モック E2E を並列実行する。Lint と Formatter は検出のみとし、違反や差分を失敗として扱う。成功・失敗時のモック E2E レポートとキャプチャを artifact に14日間保存する。

AWS 資格情報や実ユーザーの秘密情報を CI に渡さない。実 Cognito の検証とデプロイは明示的な手動実行を維持する。PR イベントには `pull_request` を使い、ワークフローの権限はリポジトリの読み取りに限定する。

## トレードオフと代替案

- 実 Cognito の E2E も自動化する：実環境への変更と資格情報管理が必要になるため、通常の PR 検証には含めない。
- キャプチャを失敗時だけ保存する：容量を抑えられるが、成功した画面の見た目を確認できないため、既存のモック画面キャプチャは成功時も保存する。
- CI が整形修正を Push する：変更がレビュー中に増えるため採用せず、修正は開発環境で行う。

詳細は [CI の検証範囲と artifact](../ci.md) を参照する。
