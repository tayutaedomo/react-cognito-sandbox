# ADR 0014: メール MFA の最小 POC で復旧を管理者対応にする

## 目次

- [背景](#背景)

- [代替案と戻し方](#代替案と戻し方)

## ステータス

提案。

## 背景

既存プールはメールのみの自己パスワード復旧を使用する。メール MFA はこの復旧方針と併用できない。SMS の配送基盤や電話属性の確認を追加せず、SES サンドボックスでメール MFA を検証したい。

## 決定と影響

メール MFA を有効にする構成では `AccountRecoverySetting` を `admin_only` にする。MFA は OPTIONAL を維持し、TOTP とメールをユーザーごとに有効化・優先設定する。

変更は既存ユーザーを含むプール全体に適用される。メール MFA を使わないユーザーも自己パスワード復旧を利用できなくなる。Managed Login の復旧導線が存在しても復旧コードは発行できない。復旧は管理者の既存 AWS 操作で行い、公開アプリに管理者復旧 API を追加しない。

## 代替案と戻し方

電話番号を確認して SMS 復旧を併用する案は、配送基盤と属性管理が増えるため今回採用しない。別プールは既存のデバイス・認証経路との組み合わせを再構築するため採用しない。

戻す際はユーザーのメール MFA を無効化し、Terraform のメール MFA を無効化した構成へ変更して、復旧を `verified_email` に戻す。送信元を Cognito の既定送信へ戻す場合は SES Identity ARN の設定を null にし、plan の差分を確認する。既存の TOTP 登録とデバイス記憶を削除する必要はない。既に変更したパスワードや失効させたセッションは復元されない。

詳細は [MFA と復旧の組み合わせ](../mfa-and-recovery.md) を参照する。
